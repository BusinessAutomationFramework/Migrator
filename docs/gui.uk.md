# GUI

Локальна веб-панель для налаштувань і контролю за процесом, що працює лише
з файловою системою. Вона НІКОЛИ не звертається до 1С/COM/BridgeTool
напряму - запускає перенос як ОКРЕМИЙ процес `python -m migrator run ...`
і читає лог-файли, які цей процес пише.

## Запуск

```bash
python -m migrator gui                    # http://127.0.0.1:8765
python -m migrator gui --host 0.0.0.0 --port 9000
```

Потребує встановлених залежностей з `requirements.txt`
(`pip install -r requirements.txt`), включно з `python-multipart` (потрібна
для обробки HTML-форм у FastAPI).

## Сторінки

### Dashboard (`/`)

Перелічує кожен корінь завдань з `migrator.config.yaml`, і кожне завдання,
знайдене в ньому (папка з `schema.yaml`), з часовою міткою і останнім
рядком логу останнього запуску.

### Редактор схем (`/schema/<корінь>/<завдання>`)

Текстове поле з "сирим" YAML над `schema.yaml` завдання:

- **Save** - спочатку пише у тимчасовий `.yaml.tmp` файл, валідує через
  `migrator.schema.load_schema()`, і лише ПОТІМ перезаписує справжній файл
  (тож зламане редагування ніколи не затирає робочу схему).
- **Validate without saving** - та сама валідація, через AJAX, без жодного
  доторку до файлу.
- Невелика форма для негайного запуску переносу, опційно з `--limit N` для
  швидкого смоук-тесту.

### Live-монітор (`/monitor/<корінь>/<завдання>`)

Вибір сесії (кожен минулий запуск, найновіший спочатку) плюс три логи, які
пише запуск, автооновлення кожні 2 секунди, поки процес ще виконується:

- `engine.log` - лог оркестрації (кроки читання/запису/каскаду), пише
  Python-сторона.
- `write_progress.log` - пооб'єктний прогрес запису, пише САМ BridgeTool
  (BSL).
- `bridge_startup.log` - власний лог життєвого циклу запуску BridgeTool,
  включно з версійним банером, який він звітує при відкритті.

### Settings (`/settings`)

Перегляд і редагування реєстру коренів завдань `migrator.config.yaml`
напряму - того самого файлу, який читає
`migrator.config.resolve_task_dir()`.

## Що свідомо НЕ робить

Немає автентифікації, немає багатокористувацької черги процесів, немає БД -
це локальний, однооператорський інструмент. Стан процесу ("яке завдання
зараз виконується") живе в пам'яті самого процесу GUI; перезапуск GUI
втрачає цей стан у пам'яті (самі лог-файли не зачіпаються).
